# Signing in, and getting back in

---

## Use a passkey if you can

A passkey is your fingerprint, face or device PIN standing in for a password. It cannot be guessed,
it cannot be phished off you by a fake sign-in page, and there is nothing to steal from the server,
because the server never holds anything that would let somebody in.

Add one from your account screen. Keep a password as well, for the machine you do not have with you.

## Codes from an app

If you would rather use six-digit codes, add an authenticator app. Same idea, slightly more typing,
and much better than a password on its own.

## Recovery codes: print them

When you turn on either of the above, you are shown a set of one-time recovery codes. **You are shown
them once.** Print them or write them down, and keep them somewhere that is not the computer you sign
in from.

Nobody can show them to you again. The server keeps only a scrambled version, which is exactly why a
stolen copy of the server's data does not hand somebody your account.

## If you are locked out

**Wrong password a few times too many**, and the server stops answering you for a while. Wait. It
clears on its own. Trying harder makes the wait longer.

**Lost your device**, and you have a recovery code, so use it and then set up a new one straight
away.

**Lost your device and the codes**, so ask your hosting provider. They can help because it is their
server, and they will want to be sure you are you before they do.

## Sign-in links

Where your hosting provider has set the panel up to send mail, you can be sent a sign-in link by
email. It works once and then expires, so if one has stopped working it has been used or it is too
old, and asking for a new one is the answer. Not every deployment has this, and if you cannot see the
option it is because your provider has not configured it.

## What good practice looks like

A different password here from anywhere else, a passkey where you can, and recovery codes on paper
rather than in a file on the desktop called passwords.
