# What may go into a customer bundle. Everything else fails the build.
#
# This replaced a blocklist that grepped for four literal prompt strings. A
# blocklist catches what somebody thought of on the day it was written: it would
# not have noticed a new prompt, a renamed one, or a knowledge file, and it did
# not notice that thirty-two test files, a book transcriber and the whole
# upgrade desktop were going out to customers. An allowlist makes adding
# something to the artifact a deliberate line in this file.
#
# One pattern per line, matched against paths relative to the staged root, with
# `*` matching within a path segment and `**` matching across segments. A line
# ending in `/` allows an empty directory and nothing inside it.
#
# Adding a line here is a decision about what a customer receives. If you are
# not sure, leave it out and let the build fail: a missing file is a broken
# install somebody notices, and an extra file is a leak nobody does.

# ── The panel itself ─────────────────────────────────────────────
app/backend/*.js

app/backend/*.html
app/backend/.env.example
app/backend/control/**/*.js
# The shipped model catalogue: what each provider's models are called, cost and
# can do. Data rather than code, so the glob above does not reach it. A customer
# install needs it, and an operator replaces it from the data directory without
# a release.
app/backend/control/modelCatalogue.json
app/backend/provisioning/**/*.js
app/backend/maintenance/**/*.js

# Which product this bundle is. Written by the bundle script; always panel.
app/PRODUCT

# The voice service's source and its setup script. The model weights and the

app/backend/tts/*.txt
app/backend/tts/*.md

# Created at install time and must be empty in the artifact. A file appearing
# under it is somebody's upload, so the pattern deliberately allows the
# directory and nothing in it.
app/backend/uploads/
